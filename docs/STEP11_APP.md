# 11단계 접속 앱 화면

앱 이름은 **최 부장 비밀 자료실**입니다. 기존 자료실의 첫 화면에 manifest와 PNG 아이콘,
브라우저 설치 안내, 연결 상태 및 기기 승인 상태 표시를 추가했습니다. 별도 접속 프로그램은 만들거나 설치하지 않습니다.

첫 화면에 **기기 승인 요청**과 **승인 결과 확인** 버튼을 제공합니다. 로그인만으로는 메모 API를 호출하거나
메모·편집기를 표시하지 않습니다. 별도 서버 상태 확인이 등록 기기를 확인한 경우에만 기존 화면을 엽니다.
승인 요청 응답은 자료를 열지 않으며 대기·거부·미등록·불명확·연결 실패는 닫힌 상태를 유지합니다.
오프라인·로그아웃·화면 숨김·확인 유효기간 만료·API의 401/403 때 화면 자료를 지우며 늦은 응답도 폐기합니다.

현재 운영 서버에는 브라우저용 기기 승인 상태 조회·요청 계약이 없습니다.
새 `/api/device-approval` 경로는 GET/POST에 **503·unavailable·registered:false**만 반환하는 안전한 연결 대기 경로입니다.
실제 요청 접수·기기 등록·승인 권한을 생성하지 않으며 현재 구현에서 자료실은 닫힌 상태를 유지합니다.
이 연결 대기 경로를 포함한 버전은 실제 등록 기기도 열 수 없으므로 운영 계약 연결·검증 전 배포하지 않습니다.
승인된 기기가 열리는 화면 시험은 가상 서버 응답 시험이며 운영 승인 완료 증거가 아닙니다.
로그인·메모 조회 성공·앱 설치·앱 창 실행을 기기 승인으로 간주하지 않습니다.
실제 승인 상태 조회·승인 요청은 운영 엔진이 확인된 상태를 제공하는 별도 계약 없이는 연결하지 않습니다.
기기 키·토큰을 localStorage·sessionStorage·IndexedDB·서비스 워커 캐시에 저장하지 않습니다.
기존 메모 API·판정기·탐지기·서버 인증과 HttpOnly 갱신 쿠키 처리는 보존합니다.
기존 자료 API를 새 기기 승인 등록부로 변경하지 않았습니다. 화면을 직접 변경한 요청의 서버 차단은
기존 로그인·소유자 검사와 운영 릴레이의 기기 검사에 의존하며, 이번 화면 숨김만으로 서버 기기 검사를 증명하지 않습니다.

화면 전용 응답 계약은 `{schema:'aleph.device-access.v1', state, registered}`입니다.
운영 어댑터 연결 뒤 GET의 `state:'registered'`와 `registered:true`가 함께 있어야 화면을 엽니다.
POST 결과는 열림 근거로 쓰지 않습니다. 확인은 최대 60초 및 로그인 만료 이내로만 유지합니다.
이 형식을 기존 판정기 요청에 추가하지 않으며 운영 엔진의 기기 등록 계약과 같다고 간주하지 않습니다.
어댑터 구현에는 승인 요청·조회 주소, 인증 방식, 현재 기기의 소유 증명과 주체 연결,
승인·거부·회수 결과 형식이 필요합니다. 헤더·사용자 입력·임의 쿠키·로그인 성공을 등록 증거로 쓰지 않습니다.

서비스 워커는 공개 `/offline.html` 안내만 캐시합니다. 메모·인증 API·첫 화면을 캐시하지 않습니다.
API는 탐색 요청이어도 가로채지 않으며, 서버의 401·403 등 거부 응답을 오프라인 성공 응답으로 바꾸지 않습니다.
첫 화면 탐색의 네트워크 실패에만 안내를 제공합니다. 처음 방문부터 오프라인이거나
서비스 워커를 지원하지 않는 브라우저에서는 오프라인 안내가 준비되지 않을 수 있습니다.

## 실행과 확인

터미널에서 `npm.cmd run build -- --local`을 실행합니다. 이 명령은 배포하지 않습니다.
배포 반영은 이 변경이 포함된 버전을 공식 Vercel 배포 절차로 올린 뒤 확인해야 합니다.
11단계 저장점의 설정 단계는 11입니다. 기존 10단계 복원 기능·주소·규칙은 보존하며 실제 승인 연결은 미완료로 기록합니다.

Vercel의 **Deployments → 변경 버전 → Visit**에서 새 이름·접속 상태를 확인하고,
지원 브라우저에서 **자료실 앱 설치** 또는 브라우저 메뉴의 **앱 설치 / 홈 화면에 추가**를 누릅니다.
설치 안내·앱 창 표시가 나와도 기기 승인 상태를 바꾸거나 자료를 열면 안 됩니다.
개발자 도구 **Application → Manifest**에서 이름과 두 아이콘을 확인합니다.
**Application → Service Workers**에서 활성화를 확인한 뒤 **Network → Offline**을 선택하고 새로고침하면
오프라인 안내만 표시돼야 합니다. 온라인으로 돌리고 **연결 후 다시 열기**를 누릅니다.
**Application → Cache Storage**에는 이 앱의 공개 오프라인 안내만 있어야 합니다.

화면 가상 시험: `node --test --test-isolation=none test/device-access.test.mjs test/app-shell.test.mjs`.
승인 전에는 메모 API 호출 0건·메모 DOM 0건이며 요청 버튼만 눌러도 그대로여야 합니다.
별도 GET에서 등록 기기 확인을 반환하는 가상 서버 응답 뒤에는 기존 메모 화면·편집이 열리고,
거부·오프라인 뒤에는 빈 화면으로 돌아와야 합니다.

정상: 서버의 등록 기기 확인 뒤 본인 로그인·메모 CRUD·세션 갱신·로그아웃 흐름 유지, 등록 정상 단건 가상 판정 `allow`.
거부: 비로그인 API 401, 타인 메모 404, 타인 소유자 지정 403, 미등록 가상 판정 `deny`·`device_not_registered`,
복합 위험 가상 판정 `step_up`, 판정기를 거친 전체 목록·공지 쓰기 `deny`.
로컬 가상 시험은 실제 계정·배포·운영 엔진·심판 결과를 증명하지 않습니다.
