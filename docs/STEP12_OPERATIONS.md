# 12단계 탈환 작전실 요약 화면

자료실에서 로그인 후 **탈환 작전실 → 작전실 새로고침**을 누릅니다.
화면은 인증된 `GET /api/operations` 응답만 표시하며 메모 API를 조회하지 않습니다.
별도 **제출 자기 점검 기록**은 `GET /api/checks`가 읽은 `artifacts/submission.json`의 가린 항목과 네 수치를 같은 응답으로 표시합니다.
서버에 이 파일이 없으면 해당 배포의 공개 주소에 GET 세 건을 새로 보내 같은 형식의 가린 결과를 만듭니다.
실제 HTTP 응답을 하나도 확인하지 못하거나 배포 커밋을 확인할 수 없으면 503·확인 불가로 두고 수치를 표시하지 않습니다.
파일이 있는데 내용이 잘못됐거나 현재 배포 커밋과 다르면 새 점검으로 대체하지 않고 503으로 중단합니다.
제출 묶음 파일을 Git에 추가하거나 브라우저에 원문을 내보내어 이 상태를 채우지 않습니다.
이 화면 요약은 파일이 실제 서버 환경에 제공된 범위의 자기 점검이며 41종 심판 결과가 아닙니다.
구현된 판정 규칙은 `RULE_IDS`에서 읽습니다. 구현된 규칙 수는 운영 판정 성공 횟수가 아닙니다.

현재 운영 판정·탐지·회수·복구 결과 조회 계약은 제공되지 않았습니다.
실제 서버에서는 `connected: false`, 각 결과의 `state: not_run`, 수치 `null`, 빈 기록을 반환합니다.
미실행은 0건 성공이나 0건 실패가 아닙니다. API 조회 오류는 확인 불가이며 이전 결과를 지웁니다.
실제 승인 미연결 때문에 자료 화면이 열리지 않는 기존 동작은 유지합니다.
작전실의 가린 요약 조회는 기존 로그인 검증을 사용하며 자료 접근 권한을 부여하지 않습니다.

`src/operations.mjs`의 `loadRecords`는 추후 공식 서버 결과 조회 계약을 연결할 경계입니다.
현재 운영 어댑터는 없으며 브라우저·쿼리·본문·공개 JSON·가상 시험 결과를 기록으로 사용하지 않습니다.
연결 시 서버 어댑터는 실제 API 응답을 검증한 기록만 다음 화면 전용 형식으로 전달해야 합니다.
이 형식은 운영 엔진의 요청·응답 계약을 대체하지 않습니다.

- 공통: `source: actual_api`, `kind`, `outcome`, UTC ISO `at`, 실제 응답 `httpStatus`.
- `decision`: `allow / deny / step_up`, 현재 구현된 `ruleIds`만 허용.
- `detection`: `observe / propose_revocation`. 회수 제안은 회수 완료가 아닙니다.
- `revocation`: `revoked / failed`. `revoked`는 집행 API의 완료를 확인한 기록만 전달해야 합니다.
- `recovery`: `restored / failed`. 완료에는 `versionVerified: true`와 실제 복구 대조를 마친 `versionSha256`이 필요합니다.

이름·계정·기기 ID·메모 제목·본문·토큰·키·원문 오류는 응답에서 제외합니다.
버전은 자유 문자열 대신 검증된 SHA-256 지문만 표시합니다.
서버 요약은 반환하는 가린 기록에서 계산하며 브라우저도 동일한 기록으로 합계를 대조합니다.
대조 실패 시 전체 결과를 지우고 확인 불가로 표시합니다. 조회 시각과 사건 시각을 구분합니다.
응답 범위의 기록 수이며 전체 운영 누적 수나 41종 공격 방어 수가 아닙니다.
결과 목록이 일부만 전달되면 그 목록의 결과만 집계합니다.

로컬 확인: `node --test --test-isolation=none test/operations.test.mjs test/device-access.test.mjs test/app-shell.test.mjs`
정상 가상 서버 기록의 집계·가린 기록 일치와 비로그인 401, 다른 메서드 405, 잘못된 기록 503을 확인합니다.
시험의 실제 API 표식은 가상 어댑터 입력이며 실제 운영·심판 결과가 아닙니다.
현재 설정 단계 11과 기존 주소·허용 경로·규칙·학습 DB를 보존하며 저장점·배포는 별도 요청입니다.

## 1~11단계 정상·금지 요청 실측표 작성 절차

이 절차는 새로 실행할 운영 시험입니다. 아래 표는 계획이며 이번 문서 작성에서 실제 요청을 보내지 않았습니다.
과거 로컬 시험 통과, 화면 문구, 설치 성공, JSON 생성 결과를 실제 API 결과 칸에 옮기지 않습니다.
현재 승인·운영 결과 조회는 미연결이므로 정상 자료 화면과 실제 회수 완료를 확인했다고 쓸 수 없습니다.

1. **대상 고정:** 공식 Vercel의 **Deployments → 대상 배포 → Visit**에서 배포 주소·커밋을 확인합니다.
   시험 실행 번호, 대상 배포 커밋, 정책 버전, 시험 범위를 표 위에 적습니다. 같은 표에서는 동일한 배포·정책을 사용합니다.
   변경·복구·재배포하면 새 실행 번호로 표를 복사하고 정상·금지 요청을 모두 다시 측정합니다.
   11단계 문서의 운영 연결 전 배포 제한을 지키며, 이 절차 때문에 임의 배포나 기기 등록을 만들지 않습니다.
2. **기록 준비:** 시험 계정 A/B와 별도로 만든 임시 가상 메모만 사용합니다.
   표의 `<시험 메모>`는 비공개 작업 환경에서만 실제 ID로 바꾸고 공개 표에는 그대로 가립니다.
   복원 대상 B 메모는 조회·해시 대조만 하며 CRUD 연습으로 수정·삭제하지 않습니다.
   요청 ID는 응답 또는 공식 서버 기록이 제공한 값을 그대로 사용합니다. 요청 ID가 없으면 `미확보`로 적고 증거 부족으로 남깁니다.
   임의 UUID·행 번호·자료 ID·`X-Resource-Id`를 서버 요청 ID로 대신 쓰지 않습니다.
   플랫폼 추적 ID는 그 ID로 대응 서버 기록을 찾을 수 있을 때만 출처를 함께 적고, 엔진 `requestId`와 구분합니다.
3. **실제 요청:** 개발자 도구 **Network → Preserve log**를 켜고 실제 정상 요청부터 보냅니다.
   메서드·가린 경로·HTTP 상태·허용된 결과 코드·서버 요청 ID·응답 확인 시각을 한 행에 기록합니다.
   확인 시각은 실제 응답을 받은 UTC ISO 시각이며 사건 시각이나 표 작성 시각으로 대신하지 않습니다.
   로그인·갱신 등 응답에 인증값이 있는 요청은 상태·고정 코드만 옮깁니다. HAR·원문 응답·전체 헤더는 공개 기록에 붙이지 않습니다.
4. **금지 요청과 보존 확인:** 같은 배포에서 대응 금지 요청을 보냅니다. 공식적으로 허가된 시험 경로와 사건만 사용합니다.
   거부 응답을 기록한 뒤 정상 주체로 다시 읽어 원본 자료·소유자·다른 자료·감사 기록이 보존됐는지 확인합니다.
   보존 확인 GET도 별도 행에 요청 ID·확인 시각을 남기고 공개 기록에는 `일치/불일치`만 적습니다.
   금지 요청에 성공 응답이 오면 `기대 불일치`입니다. 5xx·시간 초과·미연결은 정상적인 정책 거부로 통과 처리하지 않습니다.
5. **가린 서버 기록 대조:** 각 응답의 요청 ID로 공식 서버 기록을 찾아 같은 결과 코드·HTTP 상태·대상 배포·정책 버전인지 비교합니다.
   판정기는 응답과 기록의 `requestId` 일치도 확인합니다. 엔진의 허용 뒤 최종 자료 API 결과는 별도 행으로 기록합니다.
   현재 자료 API에는 명시적인 요청 ID 응답이 없고 작전실 기록도 요청 ID를 전달하지 않습니다.
   공식 추적 기록을 확보하기 전에는 이 화면만으로 실측표의 증거 대조를 완료할 수 없습니다.
   운영 기록 연결이 없는 항목은 `미연결`, 요청은 실행했지만 ID·대응 기록이 없는 항목은 `증거 부족`으로 남깁니다.
6. **양쪽 결과 검수:** 단계별 정상 허용과 금지 거부가 모두 실제 응답·요청 ID·시각·대응 서버 기록으로 확인된 경우에만 `실측 일치`로 표시합니다.
   정상만 허용되거나 금지만 거부된 단계는 완료가 아닙니다. `step_up`은 자료 접근 거부나 회수 완료와 구분합니다.
   회수 제안과 집행 API의 접수 응답만으로 회수 완료를 표시하지 않습니다. 실제 회수 뒤 금지 기기의 거부와 정상 기기의 허용이 모두 필요합니다.
   동일 응답을 여러 행에서 참조할 수 있지만 요청 ID로 중복 제거하여 집계하고, 호출 횟수·시험 항목 수·공격 종류 수를 구분합니다.

아래를 하나의 표로 복사해 사용합니다. 각 행의 **실제 API 결과·요청 ID·확인 시각·서버 대조**는 실제 실행 뒤에만 채웁니다.
`미실행` 행에는 HTTP 상태·허용/거부 수치·확인 시각을 만들어 넣지 않습니다.
한 행은 실제 요청 한 건입니다. 반복·세션 갱신·추가 CRUD·각 원본 API 메서드는 행을 복제해 개별 기록합니다.
HTTP 상태가 정해지지 않은 운영 엔진 경로는 공식 계약의 기대 결과를 먼저 확정하고, 관측 결과에 맞춰 기대값을 사후 변경하지 않습니다.

### 41종 총공세의 미실행 처리

위 표의 행 수는 41종 공격 수와 다릅니다. 공식 총공세 목록의 시험 ID·공격 이름·기대 결과를 받은 뒤 같은 표 형식에 행을 추가합니다.
목록을 받지 않은 상태에서 임의로 41개 이름을 만들거나 위 행에 공격 번호를 배정하지 않습니다.
현재 41종 시험은 **미실행, 실측 확인 항목 없음, 통과 수 미집계**입니다. 미실행을 41/41 또는 통과로 바꾸지 않습니다.
공식 시험별 실제 응답·요청 ID·확인 시각·대응 서버 기록을 확보하고, 정상 요청도 계속 허용됨을 측정한 뒤에만 항목별 실측 일치를 기록합니다.
41종의 금지 요청 방어와 정상 사용자 허용, 12단계의 공식 판정 결과를 각각 확인해야 합니다.
실측표의 일치 표시나 작전실 성공 문구 자체를 심판 통과로 보고하지 않으며, 차별화 과제는 가산 과제로 따로 기록합니다.
